# Kharcha Mobile Design QA — 2026-09-21

Scope: current Expo mobile implementation after the 20-node Figma migration, checked against the supplied Kharcha brand asset pack and mobile usability/accessibility heuristics.

## Audit result

### P0 — blocking

| Issue | Evidence | Resolution |
| --- | --- | --- |
| App content can overlap the Android status bar | Root shell used React Native core `SafeAreaView`, which does not provide reliable Android system-bar insets | **Fixed** — app, loading state, and lock state now use `react-native-safe-area-context` with top/left/right/bottom edges |
| Brand/runtime asset paths were not configured | Expo config had no supplied app icon, adaptive icon, splash or favicon | **Fixed** — optimized supplied assets are now in `assets/images/` and referenced by Expo config |

### P1 — high impact

| Issue | Evidence | Resolution |
| --- | --- | --- |
| Product accent did not match the supplied brand | UI used the Figma reference blue `#1F6FEB`, while the approved Kharcha asset pack defines `#0074FC` | **Fixed** — official brand tokens now drive the product accent |
| Primary text was inconsistent with the brand pack | Figma reference text `#262730` conflicted with approved Kharcha text `#111827` | **Fixed** — brand text token is now centralized and used by the design system |
| Bottom sheets looked like two different products | High-use sheets mixed 28px corners, 13–17px control radii, 700–900 weights and different backdrops | **Fixed** — high-use sheets now use 20px sheet corners, 10/12px controls, 600 weight and a shared neutral backdrop |
| Several frequent touch targets were undersized | Header actions/filter chips/settings badge and some sheet controls were 32–42px | **Fixed** — high-use interactive controls are raised to at least 44px where applicable |
| Header was disconnected from the supplied identity | App shell used text-only branding | **Fixed** — official Kharcha mark is used alongside the native wordmark |

### P2 — non-blocking follow-up

1. **Icon language is still mixed.** Category, wallet and some navigation affordances use emoji/text glyphs. The supplied package contains the Kharcha brand mark but not a complete product icon family, so replacing these with arbitrary icons would reduce authenticity. Next design-system pass should adopt one consistent icon set and map every category/provider.
2. **Some migrated screens still contain hard-coded English.** Budget and Reports include strings that do not yet fully participate in the existing Nepali translation system.
3. **Bottom sheets remain individually styled.** Their visual contract is now aligned, but extracting a shared `ModalSheet` primitive would prevent future drift.
4. **Real-device visual QA is still required.** CI can validate syntax/config/bundling but not status-bar height, gesture navigation, keyboard overlap, font scaling or device-specific rendering.

## Acceptance criteria for this QA patch

- No app content renders under the mobile status bar.
- Loading, locked and normal states respect all safe-area edges.
- Official Kharcha blue `#0074FC`, icon background `#F7FAFF`, dark brand background `#0F172A` and text `#111827` are represented as explicit brand tokens.
- Expo app icon, Android adaptive icon, monochrome icon, splash and web favicon resolve from repository assets.
- High-use mobile controls meet the 44px interaction target where the previous implementation fell below it.
- Target bottom sheets do not use 28px top corners or 700/800/900 text weights.
- Domain tests, dependency audit, Expo configuration validation and Android JS bundling pass before merge.

## Device verification checklist

After pulling this release to a phone:

- Check the top header on Android with gesture navigation and three-button navigation.
- Open Add Transaction, Settings, Udhaaro, Remittance, Security and Reminder sheets; confirm bottom controls remain above the system gesture area.
- Test smallest available phone width and a large-font accessibility setting.
- Open the keyboard in amount/note fields and confirm the active input + primary action remain reachable.
- Confirm launcher icon, adaptive mask, splash light/dark presentation and status-bar contrast.
